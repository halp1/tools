# Scoreboard tool, PWA/offline, back button, cross-platform counter shortcuts

Date: 2026-08-07

Four pieces of work in one pass. They share no code beyond the existing design system,
so they can be built in any order.

## 1. Scoreboard tool (`/scoreboard`)

A universal game scoring tool: set up players and the amounts you score by, then tap
buttons to adjust each player's score. Works for any number of players.

### Screens

One route, two phases held in state (`'setup' | 'board'`).

**Setup**

- Player rows: name input + remove button. "Add player" appends a blank row.
- Step amounts: chips of positive numbers (default `1`, `5`, `10`). Add via a number
  input, remove via an `x` on each chip. At least one amount is required.
- Checkbox: enable the custom-amount button on the board.
- "Start scoring" is disabled until at least one player has a non-empty name and at
  least one step amount exists. Blank-named players are dropped on start.

**Board**

One card per player:

```
┌────────────────────────────────┐
│ Alice                      12  │
│ [-10][-5][-1][+1][+5][+10][ ± ]│
└────────────────────────────────┘
```

- Name left, score right, rendered with `NumberFlow` (already a dependency, matches
  the counter tool).
- Buttons wrap: one `-N` and one `+N` per configured step amount, descending negatives
  then ascending positives. Minimum 44px tap targets.
- The leader (strictly highest score, only when scores differ) gets an accent border
  and accent score colour.
- `±` (only when the custom amount is enabled) expands an inline row inside that card:
  a number input plus `−` and `+` apply buttons. Applying collapses the row.

Board-level controls:

- **Undo** — reverts the last score change; label names it, e.g. `Undo Alice +5`.
- **Reset scores** — zeroes every score, keeps players and amounts. The "new round"
  path, so nobody retypes names.
- **Edit setup** — returns to the setup screen with scores preserved.
- **New game** — clears everything back to a fresh setup screen.

Layout: single column on mobile, auto-fill grid on desktop.

### Persistence

State lives in `src/lib/scoreboard.svelte.ts` so the page component stays presentational.
The module owns the game state, the mutations, and localStorage sync.

- Written to `localStorage` under one key on every change, with a `savedAt` timestamp.
- On load, state older than **6 hours** is discarded and the user lands on a fresh
  setup screen. Any change refreshes the timestamp.
- Malformed or version-mismatched stored data is discarded rather than trusted.
- The undo stack is in-memory only; it is not persisted.

## 2. PWA + offline

- **Prerender everything.** `src/routes/+layout.ts` exports `prerender = true`. Every
  tool is pure client-side, so prerendering makes cold offline loads of any route work
  rather than only in-app client-side navigation.
- **`src/service-worker.ts`** precaches `build`, `files`, and `prerendered` from
  `$service-worker`. Cache-first for precached assets; network-first with cache
  fallback for navigations. Old version caches are deleted on activate. SvelteKit
  auto-registers the worker in production builds.
- **`static/manifest.webmanifest`** — standalone display, `#0e0e0e` background and
  theme colour, name `HALP/TOOLS`.
- **Icons** — 192, 512, and a maskable 512 PNG. A black tile with the lime corner
  bracket from `.card::before` plus a lime slash. Generated by a one-off,
  dependency-free Node script (raw RGBA buffer + `node:zlib` PNG encoding); the PNGs
  are committed and the script is kept in `scripts/`.
- **Self-hosted fonts** — `Anta` and `DM Mono` woff2 files in `static/fonts`, declared
  with `@font-face` in `layout.css`. The Google Fonts `<link>` and `preconnect` tags
  are removed from `app.html` so the app renders identically offline.

## 3. Back button

A `←` link in the sticky layout header, left of the `HALP/TOOLS` wordmark, rendered
only when the current pathname is not `/`. One implementation in `+layout.svelte`
covers every current and future tool, and it stays reachable while scrolling.

## 4. Counter shortcuts, Mac + Windows

`src/lib/platform.svelte.ts` exposes an SSR-safe `isMac` (false during SSR, resolved
from `navigator` in the browser).

Key handling in the counter:

- Undo: `Ctrl+Z` or `⌘Z`.
- Redo: `Ctrl+Y`, `Ctrl+Shift+Z`, or `⌘⇧Z` (the Mac convention).
- Plain-key shortcuts (`R` for reset, arrow keys) require no modifiers. This fixes an
  existing bug where `⌘R`/`Ctrl+R` triggered a reset and blocked page reload.

The displayed shortcut list re-labels itself by platform: `⌘ Z` / `⇧ ⌘ Z` on Mac,
`Ctrl Z` / `Ctrl Y` elsewhere.

## Testing

The project has no test runner and this is all interactive UI, so verification is
`bun run lint`, `bun run check`, and `bun run build` passing, plus manual exercise of
each flow: scoreboard setup → score → undo → reset → edit → expiry, offline load of
every route after a production build, back button on each tool, and counter shortcuts
on both modifier conventions.
